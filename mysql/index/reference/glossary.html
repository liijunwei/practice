MySQL Indexes — Glossary

The canonical language for this course. Terms are added only after you've met them in a lesson. Lesson 1 introduces the first five.

Index

A separate, sorted copy of one or more columns whose entries point back to the table rows that hold each value, letting MySQL jump straight to matching rows instead of scanning them all.

Avoid: cache, lookup table

Full table scan

Reading every row in a table from first to last to find matches. In EXPLAIN this is type = ALL.

Avoid: brute-force search

Index lookup (seek)

Using a sorted index to jump directly to matching entries and follow their pointers, instead of scanning. In EXPLAIN this is type = ref (non-unique) or const (unique/PK exact match).

Avoid: fast search, jump

EXPLAIN

A statement MySQL provides that prints the query execution plan — how the optimizer intends to access each table and index — without running the query.

Avoid: plan dump

Access type

The type column of EXPLAIN, describing how MySQL reaches the rows. Best to worst: const → ref → range → ALL.

Avoid: join type

Composite index (multi-column index)

An index on more than one column. Its entries are sorted by the first column, then the second, then the third — like a phone book sorted by last name, then first name.

Avoid: combined index, concatenated index

Leftmost-prefix rule

A composite index (a, b, c) can serve a lookup only if the query's equality conditions use its columns from the left — a, or a,b, or a,b,c. It can never serve b alone, because the entries aren't sorted that way.

Avoid: column-order rule, prefix matching

Filesort

What MySQL does when no index produces rows in the needed order: it collects them and sorts them itself. Shows as Using filesort in EXPLAIN's Extra column — the thing a well-ordered index eliminates.

Avoid: disk sort (it often happens in memory)

Range condition

A comparison that matches a span of the index rather than one value: >, <, >=, <=, BETWEEN, LIKE 'x%', or IN (...). In a prefix, only equality columns before the first range are used to narrow the search.

Avoid: inequality

key_len

The byte length of the index key actually used, reported in EXPLAIN. Bigger means more prefix columns were consumed — the objective ruler for the leftmost-prefix and range rules.

Avoid: key size, index width

Covering index

An index that contains every column the query needs (in SELECT, WHERE, ORDER BY, GROUP BY), so MySQL answers from the index alone — Using index in EXPLAIN — and never reads the table row.

Avoid: index-only scan (that's the same idea, vendor-neutral)

Index condition pushdown (ICP)

MySQL filtering rows against the index before reading the table row, shown as Using index condition in EXPLAIN. Not the same as covering — ICP still reads the table row for missing columns.

Avoid: covering index

Implicit type conversion

MySQL casting a column's values to match a comparison — e.g. a string column compared to a number literal — which prevents the index from being used. The fix is comparing to a literal of the same type.

Avoid: silent cast, coercion

Cardinality / Selectivity

The number of distinct values in a column, shown as Cardinality in SHOW INDEX. High cardinality means each value matches few rows — a selective, index-worthy filter.

Avoid: uniqueness

Nested-loop join

MySQL's join algorithm: read the driving table one row at a time, and for each row look up the next table by the join key — a lookup that needs an index just like a WHERE column.

Avoid: loop join

Driving table

The first table in a nested-loop join, whose rows are read one at a time while every later table is looked up per row.

Avoid: outer table

eq_ref

An EXPLAIN access type meaning a lookup on a PRIMARY KEY/UNIQUE join key — exactly one row per lookup. The best join access.

Avoid: unique lookup
