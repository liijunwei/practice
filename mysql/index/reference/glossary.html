MySQL Indexes — Glossary

The canonical language for this course. Terms are added only after you've met them in a lesson. Lesson 1 introduces the first five.

Index

A separate, sorted copy of one or more columns whose entries point back to the table rows that hold each value, letting MySQL jump straight to matching rows instead of scanning them all.

Avoid: cache, lookup table

Full table scan

Reading every row in a table from first to last to find matches. In EXPLAIN this is type = ALL.

Avoid: brute-force search

Index lookup (seek)

Using a sorted index to jump directly to matching entries and follow their pointers, instead of scanning. In EXPLAIN this is type = ref (non-unique) or const (unique/PK exact match).

Avoid: fast search, jump

EXPLAIN

A statement MySQL provides that prints the query execution plan — how the optimizer intends to access each table and index — without running the query.

Avoid: plan dump

Access type

The type column of EXPLAIN, describing how MySQL reaches the rows. Best to worst: const → ref → range → ALL.

Avoid: join type
